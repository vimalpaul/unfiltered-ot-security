# OT Security Engineering

This section translates OT security requirements into implementable architecture, hardening standards, operational controls, verification and lifecycle engineering.

## Master playbook

- [OT Security Engineering, Hardening and Defensive Architecture](OT-SECURITY-ENGINEERING-HARDENING-AND-DEFENSIVE-ARCHITECTURE.md)

## Engineering principles

- Understand the process and safety context before designing controls.
- Use zones and conduits to document trust boundaries and required communications.
- Treat Purdue as a reference model, not a complete security architecture.
- Use an industrial DMZ and brokered exchange where justified.
- Restrict remote access, privileged identities and vendor connectivity.
- Apply vendor-supported hardening baselines.
- Validate endpoint, network and monitoring controls for operational compatibility.
- Protect configurations, engineering projects and recovery assets.
- Use management of change, FAT/SAT and operational acceptance.
- Require human approval for production changes and AI-assisted recommendations.
